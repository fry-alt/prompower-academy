# Обучение позы серой копией робота

Дата: 2026-09-03. Источник требований: постановка заказчика в работе над фазой 2
и [docs/jaka-zu-app-reference.md](../../jaka-zu-app-reference.md), разделы
«Ручное управление» и `MoveJ ▾ New point`.

## Задача

Сейчас поза движения набирается числами: шесть полей J1…J6 в градусах у блока
«двигаться по осям» и X/Y/Z в миллиметрах у блока «двигаться по прямой».
Подобрать так осмысленную позу нельзя — ученик крутит числа вслепую и ловит
«точка недостижима».

На планшете JAKA точку не набирают, а **показывают роботу**: жмут `New point`,
доводят руку ручным управлением до нужного места и запоминают позу. Повторяем
это в браузере, только вместо настоящей руки — серая копия модели.

## Принятые решения

**1. Поза живёт внутри блока, а не в реестре именованных точек.**
На планшете точка — отдельная именованная сущность, её можно поставить в
несколько блоков. У нас поза остаётся полями блока: не нужно новое хранилище в
AST, в сериализации Blockly и в обоих генераторах кода, а числа видно прямо на
блоке. Пересмотреть решение стоит на уроке 6 «паллетирование в цикле», где одна
и та же точка подхода нужна нескольким движениям.

**2. Обучение идёт в сцене урока, а не в отдельном окне.**
Модальное окно закрыло бы сцену, а главный вопрос при показе точки — «дотянусь
ли я до детали и не в столе ли фланец». Ответ на него даёт только сцена урока
целиком: деталь, зоны, стол, настоящий робот. Побочная выгода — не нужен второй
холст three.js и вторая камера.

**3. Блок «двигаться по прямой» тоже учится, и точка пишется полной позой.**
Сегодня в [to-ast.ts](../../../packages/blocks/src/to-ast.ts) стоит константа
`TOOL_DOWN`: любая прямая едет с инструментом строго вниз. Она уходит,
ориентация приезжает вместе с точкой. Обученная точка вдобавок гарантированно
достижима — робот только что в ней стоял, обратной кинематике есть куда
сходиться. Значения по умолчанию у новых полей RX/RY/RZ — 180/0/0, то есть
прежний «инструмент вниз»: уже собранные программы поведения не меняют.

**4. Ползунки только по суставам.**
Декартово ручное управление с планшета (X/Y/Z, RX/RY/RZ, переключение
Мир/Фланец) требует решать обратную задачу на каждое движение ползунка. Пользы
на уроках 1–5 нет: там показывают позу, а не выцеливают миллиметры.

## Что строим

### 1. Блоки — `packages/blocks/src/blocks.ts`

- У `pp_move_joint` и `pp_move_linear` появляется поле-кнопка типа `field_teach`.
- У `pp_move_linear` добавляются поля `RX`, `RY`, `RZ` в градусах, по умолчанию
  180/0/0.
- Пакет остаётся набором данных без импорта Blockly: тип поля — просто строка.
  Благодаря этому `to-ast` и `to-python` по-прежнему проверяются без браузера.

### 2. Генератор AST — `packages/blocks/src/to-ast.ts`

`TOOL_DOWN` удаляется, `moveL` читает ориентацию из полей и переводит градусы в
радианы там же, где переводит миллиметры в метры. `to-python` правок не требует:
он уже печатает rx/ry/rz.

### 3. Граница с Blockly — `components/simulator/teach-field.ts` (новый)

Регистрация кастомного поля Blockly, которое рисуется кнопкой. По клику поле
шлёт событие на контейнер холста с идентификатором блока. Blockly импортируется
только здесь и в редакторе — так же, как сейчас.

### 4. Перевод поз — `components/simulator/teach-pose.ts` (новый)

Две чистые функции, обе покрыты unit-тестами:

- `seedFromBlock(kind, fields, chain, fallback)` → углы суставов для копии.
  Для «по осям» это сами поля в радианах. Для «по прямой» — обратная задача от
  записанной позы; если решения нет, возвращается `fallback` (домашняя поза) и
  признак того, что записанную точку взять не удалось.
- `fieldsFromJoints(kind, joints, chain)` → значения полей блока.
  Для «по осям» — градусы, для «по прямой» — `flangePose` в миллиметрах и
  градусах.

Модуль зависит только от `sim-core`, three.js в нём нет.

### 5. Серая копия — `components/simulator/ghost-robot.tsx` (новый)

Клон загруженной модели с единым полупрозрачным серым материалом, теней не
бросает и не принимает. Стоит в тех же координатах, что настоящий робот, углы
берёт из состояния обучения.

### 6. Редактор блоков — `components/simulator/block-editor.tsx`

- Слушает событие от поля-кнопки и отдаёт наружу тип блока, его идентификатор и
  текущие значения полей.
- Умеет записать значения полей обратно по идентификатору блока. Запись меняет
  рабочую область, обработчик изменений срабатывает сам, наружу уезжает уже
  новый AST — связывать это отдельно не нужно.

### 7. Экран урока — `components/simulator/lesson-workspace.tsx`

Состояние обучения: блок, его тип и текущие углы копии. Пока оно не пусто:

- прогон программы ставится на паузу на входе в режим;
- левая колонка показывает панель обучения вместо целей задания: заголовок,
  `JointPanel` (переиспользуется как есть — он уже умеет градусы, пределы из
  URDF и подпись «упёрся в предел»), положение фланца в миллиметрах для справки,
  кнопки «Сохранить» и «Отмена»;
- в сцене рендерится серая копия.

«Сохранить» пишет поля в блок и выходит из режима, «Отмена» выходит не меняя
ничего.

### 8. Подписи — `messages/ru.json`, `messages/en.json`

Строк в JSX нет, как и везде в проекте.

## Границы

- Декартовы ползунки и переключение Мир/Фланец — не сейчас, см. решение 4.
- Перетаскивание робота мышью за фланец — не сейчас.
- Именованные точки с переиспользованием — не сейчас, см. решение 1.
- Серая копия не проверяется на столкновения: она показывает позу, а не путь.
  Проверка AABB работает при прогоне программы и остаётся единственной.

## Риск

Копия делается методом `clone()` модели `urdf-loader`. Если клон потеряет карту
суставов, запасной путь — вторая загрузка того же URDF: браузер отдаст файл из
кэша. Проверяется первой задачей плана, до всего остального.

## Definition of Done

- Обучение работает на обоих блоках движения: копия появляется в позе, записанной
  в блоке, ползунки её двигают, «Сохранить» меняет поля блока и вкладку «Код».
- Программа с обученными точками проходит задание урока 4 до конца.
- Unit-тесты: чтение ориентации в `to-ast`, оба направления перевода поз,
  поведение при недостижимой записанной точке.
- E2E-тест: кнопка → копия и панель → ползунок → «Сохранить» → поле блока и
  сгенерированный Python изменились; «Отмена» не меняет ничего.
- `npm run typecheck`, `npm test`, `npm run test:e2e` зелёные.
