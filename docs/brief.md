## 1. Контекст

**Заказчик:** ПРОМЭНЕРГО АВТОМАТИКА (бренд PROMPOWER) — российская компания, продающая коллаборативных роботов (коботов). Под капотом это роботы JAKA, поставляемые под собственным брендом. Софт для программирования — тоже JAKA (JAKA Zu App, блочное программирование в стиле Scratch; JAKA SDK по TCP/IP на C/C++, C#, Python).

**Задача:** веб-платформа обучения работе с коботами PROMPOWER. Аналог Universal Robots Academy, но на русском, под линейку PROMPOWER и с браузерным симулятором, который не требует физического робота.

**Два рынка одного продукта:**
1. **B2B.** Инженеры компаний-клиентов, которые купили или рассматривают кобота. Обучение снимает нагрузку с техподдержки PROMPOWER и работает аргументом в продаже.
2. **Образование.** Школы и кружки робототехники. Тот же движок, другая упаковка: профориентация, блочное программирование, режим класса для учителя.

**Ключевая ценность:** человек программирует настоящую модель кобота PROMPOWER в браузере, без установки софта и без доступа к железу. То, что он собрал в браузере, потом запускается на реальном роботе.

**Доступы:** у меня есть полный доступ к продукции и материалам PROMPOWER — 3D-модели, URDF, спецификации, брендбук, документация. Если тебе для работы нужен конкретный файл или параметр — спрашивай прямо, я его предоставлю. Не выдумывай данные о роботах.

## 4. Симулятор

### 4.1 Модель робота

URDF и меши я предоставлю. Твоя задача:

- Конвертировать меши в glTF со сжатием Draco. Целевой бюджет: полная модель кобота — до 3 МБ. Исходные STL/DAE из ROS-пакетов весят десятки мегабайт, без конвертации первая загрузка урока займёт секунды и убьёт впечатление.
- Написать скрипт конвертации в `scripts/convert-meshes.ts`, чтобы добавление новой модели было одной командой.
- Загрузить URDF через `urdf-loader`, настроить `loader.packages` под наши пути.
- Прочитать пределы суставов из URDF и жёстко их соблюдать — робот не должен уметь встать в позу, невозможную для железа.

### 4.2 Кинематика

- **FK** — берётся из URDF-дерева бесплатно, просто выставляй углы суставов.
- **IK** — через `closed-chain-ik`, у него есть утилиты связки с URDF (`urdfRobotToIKRoot`, `setUrdfFromIK`).
- Если решение не найдено или требует выхода за пределы сустава — не двигай робота, верни ошибку в интерпретатор, покажи её пользователю человеческим языком: «Точка недостижима — цель за пределами рабочей зоны», а не «IK solver failed to converge».
- Ограничивай число итераций солвера, чтобы не подвешивать вкладку.

### 4.3 Границы точности

Не пытайся строить физический движок. Ориентир: даже вендорский офлайн-симулятор URSim от Universal Robots не моделирует столкновения с собой и окружением, не поддерживает аварийный стоп, не даёт задавать состояния входных I/O и строит идеальные траектории. Для обучения этого достаточно.

Что делаем:
- Кинематика и интерполяция траекторий — да.
- Столкновения — только через AABB (ограничивающие параллелепипеды) с объектами сцены и со столом. Столкновение звеньев робота между собой — не проверяем.
- Динамика, силы, моменты, режим force mode — нет.

Явно напиши об этих ограничениях в README проекта, чтобы никто потом не ждал от симулятора большего.

## 5. Язык программ и блоки

### 5.1 Внутреннее представление

Программа хранится как JSON-AST, а не как строка кода. Это позволяет одновременно исполнять её в симуляторе и генерировать текстовый код.

```ts
type Statement =
  | { op: 'moveJ'; joints: number[]; speed: number; acc: number }
  | { op: 'moveL'; pose: Pose; speed: number; acc: number }
  | { op: 'setDO'; index: number; value: boolean }
  | { op: 'waitDI'; index: number; value: boolean; timeoutMs?: number }
  | { op: 'gripper'; action: 'open' | 'close' }
  | { op: 'wait'; ms: number }
  | { op: 'repeat'; times: number; body: Statement[] }
  | { op: 'while'; cond: Condition; body: Statement[] }
  | { op: 'if'; cond: Condition; then: Statement[]; else?: Statement[] }
  | { op: 'setVar'; name: string; value: Expression }
  | { op: 'comment'; text: string };
```

Расширяй по мере надобности, но структуру сохраняй: дискриминированное объединение по `op`.

### 5.2 Blockly

- Блоки визуально и по смыслу повторяют команды JAKA Zu App — тот, кто учился у нас, должен узнать интерфейс, сев за реальный планшет.
- Русские подписи на блоках. Никакого рунглиша: «Двигаться по прямой», а не «MoveL линейно».
- Категории в тулбоксе: Движение, Захват, Входы/выходы, Логика, Циклы, Переменные, Ожидание.
- Два генератора кода из одного дерева блоков:
  1. `toAst()` → JSON выше, для симулятора.
  2. `toPython()` → рабочий скрипт на Python под JAKA SDK, который клиент реально запустит на железе.
- Кнопка «Показать код» — переключение между блоками и сгенерированным Python в режиме только для чтения. Это мост от блоков к тексту, важный для старших школьников и инженеров.

## 6. Виртуальный контроллер

Это ядро всего продукта. Пошаговый интерпретатор AST со следующими свойствами:

- **Пошаговое исполнение.** Одна «инструкция» за тик, чтобы работали кнопки «шаг», «пауза», «сброс», и чтобы можно было подсвечивать текущий блок в редакторе.
- **Регулируемая скорость.** Ползунок 0.25×–4×. По умолчанию 1×.
- **Состояние мира** (`WorldState`): позы всех подвижных объектов сцены, содержимое захвата, массив цифровых входов и выходов, переменные пользователя, счётчик времени.
- **Детерминированность.** При одном и том же AST и одном и том же начальном состоянии результат обязан совпадать бит в бит. Без `Math.random()`, без привязки к реальному времени. Время — счётчик тиков.
- **Журнал событий.** Каждый шаг пишет запись: что выполнено, что изменилось. Это основа и для отладки, и для автопроверки, и для будущей аналитики «где чаще всего застревают ученики».

### Автопроверка задания

Задание описывается декларативно в JSON рядом с уроком:

```json
{
  "id": "pick-and-place-basic",
  "world": { "objects": [...], "zones": [...] },
  "goals": [
    { "type": "objectInZone", "object": "cube-1", "zone": "zone-b" },
    { "type": "gripperState", "state": "open" }
  ],
  "constraints": [
    { "type": "noCollision" },
    { "type": "maxStatements", "value": 12 }
  ],
  "hints": [
    { "afterFailedAttempts": 2, "text": "..." }
  ]
}
```

Валидаторы — чистые функции `(WorldState, EventLog) => Result`. Каждый новый тип цели — новый валидатор в `packages/sim-core/validators`, покрытый тестом.

**Обратная связь при провале должна быть конкретной.** Не «задание не выполнено», а «Кубик оказался в зоне A, а нужен в зоне B» или «Захват остался закрытым в конце программы». Ошибка объясняет, что произошло и что делать.

## 7. Структура курса

Бери за основу прогрессию UR Academy — она проверена на десятках тысяч пользователей. Базовый трек там: настройка инструмента и рабочего органа, подключение входов/выходов, создание базовых программ, применение функций безопасности. Продвинутый: системы координат, переменные и условные операторы, готовый мастер для задачи упаковки.

Наш базовый курс, 6 уроков:

1. **Знакомство с коботом.** Что такое коллаборативный робот, устройство, оси, рабочая зона. Задание: привести робота в заданную позу ползунками суставов.
2. **Безопасность.** Зоны, скорости, режимы, что делать нельзя. Задание с проверкой на нарушение границ.
3. **Первое движение.** MoveJ против MoveL, скорость и ускорение. Задание: пройти три точки.
4. **Инструмент и захват.** TCP, полезная нагрузка, центр тяжести. Задание: взять и переставить деталь.
5. **Входы и выходы.** Цифровые сигналы, ожидание сигнала, связь с конвейером. Задание: забрать деталь по сигналу датчика.
6. **Полный цикл.** Паллетирование в цикле с переменными. Итоговое задание.

Продвинутый трек и отраслевые кейсы (обслуживание станка, упаковка) — после MVP.

**Формат урока:** короткая теория (MDX, 2–4 минуты чтения) → интерактивное задание в симуляторе → автопроверка → переход. Никаких длинных лекций: главное здесь — делать, а не читать.

Контент лежит в `content/courses/<slug>/` как MDX + JSON заданий. Уроки должны добавляться без правки кода приложения.

## 8. Функциональность платформы

**Для ученика:**
- Регистрация и вход, восстановление пароля.
- Карта курса с прогрессом, отметками пройденного, продолжением с последнего места.

- Сертификат по завершении курса: уникальный код, PDF на скачивание, публичная страница проверки `/verify/[code]`. Сертификат мотивирует и корпоративного инженера, и школьника — это не декоративная фича.
- Личный кабинет: пройденные курсы, сертификаты.

**Для администратора PROMPOWER:**
- Создание организаций и групп, приглашение пользователей по ссылке или списком email.
- Дашборд: кто из инженеров клиента что прошёл, сколько времени потратил, где застрял.
- Выгрузка отчёта в CSV/XLSX.
- Управление курсами: публикация, снятие с публикации, порядок уроков.

**Для учителя (режим класса):**
- Создание класса, добавление учеников.
- Живая доска прогресса: список учеников и их статус по текущему уроку в реальном времени (достаточно поллинга раз в 10–15 секунд, WebSocket на MVP не нужен).
- Возможность выдать классу конкретный урок как задание.

Режим класса — отдельная продаваемая ценность, а не бесплатное дополнение. Проектируй его как полноценный модуль.

## 9. Дизайн

Прочитай брифинг ниже как задание для арт-директора, а не как список требований к вёрстке.

**Что это за продукт визуально.** Промышленная робототехника — это точность, безопасность и инженерная культура. Не игрушка, не SaaS-дашборд, не стартап-лендинг. Ближайшие референсы по духу — интерфейсы промышленного оборудования и профессиональных CAD-систем: спокойные, плотные, читаемые часами подряд. При этом продукт должен быть дружелюбным к школьнику, который видит робота впервые.

**Правила:**
- Одна акцентная краска из брендбука PROMPOWER (я его предоставлю), всё остальное — сдержанная нейтральная шкала. Вся визуальная яркость отдана 3D-сцене и цветным блокам Blockly, они и так конкурируют за внимание.
- 3D-сцена по умолчанию на тёмном фоне: робот на светлом читается заметно хуже, силуэт теряется.
- Экран урока — три зоны: теория/задание, редактор блоков, 3D-сцена. Пользователь должен уметь менять их пропорции перетаскиванием разделителей и сворачивать теорию, когда она прочитана.
- Типографика: один-два шрифта, чёткая шкала. Никаких ALL CAPS-подписей над каждым заголовком, никакого выделения одного слова в заголовке цветом, никаких стрелок «→» в конце кнопок. Это визуальные штампы.
- Анимация только как ответ на действие пользователя. Никаких fade-in при скролле на каждом блоке.
- Пустые состояния и ошибки — это указания к действию, а не украшение. «Здесь появятся ваши сертификаты. Начните с курса „Основы работы с коботом“» лучше, чем «Пока пусто».

**Мобильная версия.** Блочный редактор на телефоне бесполезен, не притворяйся, что это не так. На мобильном доступны теория, видео, прогресс и сертификаты. Экран задания честно говорит: «Задание открывается на компьютере или планшете» — и предлагает отправить ссылку себе на почту.

**Качественный минимум, без обсуждения:** адаптив до мобильного, видимый фокус с клавиатуры, соблюдение `prefers-reduced-motion`, контраст текста не ниже AA.

## 12. Фазовый план

Не пытайся сделать всё сразу. Каждая фаза заканчивается работающей демонстрацией.

**Фаза 1 — скелет симулятора.** Одна страница: three.js, загруженный URDF робота PROMPOWER, шесть ползунков на суставы, орбитальная камера, сетка и стол. Больше ничего.
*DoD:* модель грузится меньше чем за 2 секунды, суставы двигаются, пределы соблюдаются, работает на среднем ноутбуке 60 fps.

**Фаза 2 — контроллер и блоки.** `sim-core` с интерпретатором и IK. Blockly с 6–8 блоками. Одно задание «переложи деталь из A в B» с автопроверкой. Кнопки запуск/пауза/шаг/сброс.
*DoD:* задание проходится от начала до конца, unit-тесты на интерпретатор зелёные, неверное решение даёт внятное объяснение почему.

**Фаза 3 — оболочка курса.** Аутентификация, БД, 4 урока из содержания выше, прогресс, автосохранение черновика, сертификат с публичной проверкой.
*DoD:* новый пользователь регистрируется, проходит курс целиком и получает сертификат; e2e-тест этого пути в Playwright.

**Фаза 4 — админка и режим класса.** Организации, группы, дашборд прогресса, выгрузка отчёта, класс для учителя.
*DoD:* администратор заводит группу из 10 человек и выгружает отчёт по её прогрессу.

**Фаза 5 — мост на железо.** Экспорт программы в Python под JAKA SDK. Опционально — прямое подключение к контроллеру робота по TCP/IP через серверный прокси.
*DoD:* программа, собранная в браузере, скачивается и без правок запускается на реальном коботе.

## 13. Чего не делать

- Не пиши физический движок и не подключай Rapier, Cannon или Ammo. Кинематика и AABB — потолок.
- Не завязывай `sim-core` на React или three.js.
- Не хардкодь ни одной характеристики робота — всё из URDF или из конфига плагина модели.
- Не изобретай данные о продукции PROMPOWER. Не знаешь параметр — спроси у меня.
- Не строй мультиарендную SaaS-архитектуру на MVP. Одна инсталляция для PROMPOWER, разделение по организациям внутри БД.
- Не подключай платежи. Модель монетизации пока не решена.
- Не используй `localStorage` для прогресса — он идёт в БД. Локально можно держать только несохранённый черновик программы.
