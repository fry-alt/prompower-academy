# PROMPOWER Academy

Веб-платформа обучения работе с коллаборативными роботами PROMPOWER. Человек
программирует модель кобота прямо в браузере — без установки софта и без доступа
к железу, — а собранную программу потом запускает на настоящем роботе.

Требования к продукту: [docs/brief.md](docs/brief.md).
Текущая фаза: **1 — скелет симулятора**.

## Чего симулятор не делает

Это не цифровой двойник. Границы выбраны сознательно: даже вендорский офлайн-
симулятор URSim от Universal Robots не моделирует столкновения и не считает силы,
и для обучения этого достаточно.

| Есть | Нет |
|---|---|
| Прямая и обратная кинематика | Динамика, силы, моменты, force mode |
| Интерполяция траекторий | Проверка столкновений звеньев робота между собой |
| Столкновения по AABB с объектами сцены и со столом | Точная геометрия столкновений |
| Пределы суставов из URDF | Аварийный останов, функции безопасности контроллера |

Никакого физического движка (Rapier, Cannon, Ammo) в проекте нет и не планируется.

## Что уже работает

Страница `/{locale}/sandbox`: загруженный URDF, орбитальная камера, стол и сетка,
шесть ползунков на суставы. Значения зажимаются в пределы из URDF, поэтому
поставить робота в невозможную для железа позу нельзя. Время загрузки и текущий
fps показаны в правом нижнем углу панели.

**Робот на сцене — учебная заглушка, а не модель PROMPOWER.** Настоящие URDF и
меши предоставляет заказчик; до их появления в сцене стоит шестиосевой
манипулятор из примитивов с выдуманными пределами суставов. Он помечен флагом
`isPlaceholder`, и интерфейс говорит об этом пользователю.

## Как запустить

```bash
npm install
npm run dev        # http://localhost:3000/ru/sandbox
```

Реестр npmjs из части российских сетей отдаёт первые килобайты и рвёт соединение,
поэтому в `.npmrc` прописано зеркало `registry.npmmirror.com`. Если у вас npmjs
открывается напрямую — строку можно убрать.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Дев-сервер |
| `npm run build` | Прод-сборка |
| `npm run typecheck` | TypeScript в строгом режиме |
| `npm test` | Unit-тесты `sim-core` и адаптеров (Vitest) |
| `npm run test:e2e` | Сквозной проход песочницы (Playwright) |
| `npm run convert-meshes -- <плагин>` | Сжатие мешей модели в Draco с проверкой бюджета 3 МБ |

## Устройство

```
app/[locale]/         страницы Next.js, локаль в пути
components/simulator/ сцена, загрузка URDF, панель суставов — всё, что знает про three.js
packages/
  sim-core/           кинематика и контракты. Без React и без three.js
  robot-plugins/      по каталогу на модель кобота
public/models/        URDF и меши, отдаются статикой
content/courses/      уроки в MDX и задания в JSON (появятся в фазе 3)
```

Ключевая развязка: `packages/sim-core` — чистая логика под unit-тесты,
визуализация подписывается на её состояние. Это позволит гонять задания уроков в
CI и проверять автопроверку без браузера.

Каждая модель кобота — отдельный плагин. Ни одна характеристика робота в коде не
захардкожена: пределы суставов читаются из URDF, остальное берётся из конфига
плагина. Добавление модели — новый каталог в `packages/robot-plugins/`, код
приложения не меняется.
