# PROMPOWER Academy

Веб-платформа обучения работе с коллаборативными роботами PROMPOWER. Человек
программирует модель кобота прямо в браузере — без установки софта и без доступа
к железу, — а собранную программу потом запускает на настоящем роботе.

Требования к продукту: [docs/brief.md](docs/brief.md).
Текущая фаза: **1 — скелет симулятора**.

## Чего симулятор не делает

Это не цифровой двойник. Границы выбраны сознательно: даже вендорский офлайн-
симулятор URSim от Universal Robots не моделирует столкновения и не считает силы,
и для обучения этого достаточно.

| Есть | Нет |
|---|---|
| Прямая и обратная кинематика | Динамика, силы, моменты, force mode |
| Интерполяция траекторий | Проверка столкновений звеньев робота между собой |
| Столкновения по AABB с объектами сцены и со столом | Точная геометрия столкновений |
| Пределы суставов и скорости из URDF | Аварийный останов, функции безопасности контроллера |
| Отказ вместо движения, когда точка недостижима | Разгонные профили: ускорение принимается, но время движения не меняет |

Движение по прямой обрывается в вырожденных позах — когда фланец выходит на ось
первого сустава или рука распрямляется полностью. Это не недоработка: там теряет
смысл сама постановка задачи, и настоящий контроллер ведёт себя так же. Отказ
говорит, на каком проценте отрезка путь оборвался.

Никакого физического движка (Rapier, Cannon, Ammo) в проекте нет и не планируется.

## Что уже работает

Страница `/{locale}/sandbox/{модель}`: загруженный URDF, орбитальная камера, стол
и сетка, шесть ползунков на суставы, выбор модели из линейки. Значения зажимаются в пределы из URDF, поэтому
поставить робота в невозможную для железа позу нельзя. Время загрузки и текущий
fps показаны в правом нижнем углу панели.

Курс «Основы работы с коботом» открывается уроком «Знакомство с коботом»: теория
об устройстве руки и задание, которое решается ползунками суставов, без
программы. Робота приводят в показанную серой копией позу, а затем подводят
инструмент к метке в пространстве; обе цели отмечаются в тот момент, когда
ученик до них довёл.

## Модели роботов

Каждая модель — плагин в `packages/robot-plugins/models/<slug>/`: URDF, меши и
конфиг. Ни одна характеристика робота в коде не захардкожена — пределы и типы
суставов читаются из URDF, габариты меряются по загруженной модели, остальное
берётся из конфига плагина. Переключение модели — выпадающий список в шапке,
адрес вида `/ru/sandbox/jaka-zu7` можно отправить ссылкой.

| Плагин | Что это |
|---|---|
| `jaka-zu5`, `jaka-zu7`, `jaka-zu12`, `jaka-zu15`, `jaka-zu18`, `jaka-zu20`, `jaka-zu30` | Серия JAKA Zu из репозитория производителя |
| `placeholder-6dof` | Манипулятор из примитивов, без мешей. Пример минимального плагина и быстрый объект для тестов |

**Ни одна из них не является моделью PROMPOWER.** Все помечены предупреждением,
которое видит пользователь. Правовая сторона —
[LICENSE-NOTICE.md](packages/robot-plugins/LICENSE-NOTICE.md): файла лицензии в
репозитории JAKA нет, использование временное, до получения файлов от заказчика.

### Обновить или добавить модель

```bash
npm run import-models              # забрать исходники серии Zu из репозитория JAKA
npm run import-models -- zu7       # или только одну модель
npm run convert-meshes -- --all    # сжать в glTF+Draco и разложить в public/models/
```

Исходные STL весят около 60 МБ и в репозитории не хранятся — там лежит только
результат конвертации, 4.4 МБ. Свою модель кладут руками:

```
packages/robot-plugins/models/<slug>/urdf/<slug>.urdf
packages/robot-plugins/models/<slug>/meshes/*.stl     # или .glb/.gltf
packages/robot-plugins/models/<slug>/plugin.ts        # по образцу соседей
```

и добавляют строку в [packages/robot-plugins/index.ts](packages/robot-plugins/index.ts).
Код приложения при этом не меняется.

## Как запустить

```bash
npm install
npm run dev        # http://localhost:3000/ru/sandbox
```

Реестр npmjs из части российских сетей отдаёт первые килобайты и рвёт соединение,
поэтому в `.npmrc` прописано зеркало `registry.npmmirror.com`. Если у вас npmjs
открывается напрямую — строку можно убрать.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Дев-сервер |
| `npm run build` | Прод-сборка |
| `npm run typecheck` | TypeScript в строгом режиме |
| `npm test` | Unit-тесты `sim-core` и адаптеров (Vitest) |
| `npm run test:e2e` | Сквозной проход песочницы (Playwright) |
| `npm run import-models` | Забрать исходные URDF и меши серии JAKA Zu |
| `npm run convert-meshes -- <плагин>` | Сжатие мешей модели в Draco с проверкой бюджета 3 МБ |
| `npm run convert-meshes -- --all` | То же для всех моделей сразу |
| `npm run sync-draco` | Обновить декодер Draco в `public/draco` под текущую версию three |

## Устройство

```
app/[locale]/         страницы Next.js, локаль в пути
components/simulator/ сцена, загрузка URDF, панель суставов — всё, что знает про three.js
packages/
  sim-core/           кинематика и контракты. Без React и без three.js
  robot-plugins/      реестр моделей, по каталогу на модель в models/
public/models/        собранные URDF и glTF, отдаются статикой (генерируется)
content/courses/      уроки в MDX и задания в JSON (появятся в фазе 3)
```

Ключевая развязка: `packages/sim-core` — чистая логика под unit-тесты,
визуализация подписывается на её состояние. Это позволит гонять задания уроков в
CI и проверять автопроверку без браузера.

Каждая модель кобота — отдельный плагин. Ни одна характеристика робота в коде не
захардкожена: пределы суставов читаются из URDF, остальное берётся из конфига
плагина. Добавление модели — новый каталог в `packages/robot-plugins/`, код
приложения не меняется.
